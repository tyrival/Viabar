# Viabar 年度报告 AI 总结设计

日期：2026-08-02

## 1. 目标

在不改变现有年度报告数据范围、SwiftData schema 和原始 Markdown 导出语义的前提下：

1. 在 macOS 设置中增加独立的 AI Tab，复用 Fringe 当前的 OpenAI 兼容配置能力。
2. 扩大年度报告弹窗的默认宽度和高度。
3. 为当前年份的原始年度报告生成只读 Markdown AI 总结。
4. AI 总结生成后，将窗口向右扩展为原始报告与 AI 总结各占 50% 的双栏布局。
5. 有 AI 总结时，通过气泡选择导出原始年报或 AI 总结。

## 2. 已确认边界

- AI 输入只使用当前年份原始年度报告的完整 Markdown 文本。
- 不读取项目备忘录，不扩展年度报告当前包含的业务数据。
- AI 结果为只读 Markdown，不提供编辑能力。
- 允许重新生成；新结果成功后覆盖旧结果。
- 切换年份时清空已有 AI 结果、错误和请求状态，并收起右侧面板。
- 本功能不修改任何 `@Model`、SwiftData schema、主库、回收站库或备份格式。
- AI 服务配置使用 `UserDefaults`，API Key 使用 Keychain，不写入 SwiftData 或备份。

## 3. 方案比较与选择

### 方案 A：直接复用 Fringe 的 OpenAI 兼容调用链（采用）

将 Fringe 中已存在的服务商配置、Keychain、模型列表与 `v1/chat/completions` 调用模式移植到 Viabar，并针对年度报告定义独立的提示词和请求入口。

优点：设置内容与用户要求完全一致；范围清晰；不引入第三方依赖；不改数据库。

### 方案 B：只支持固定 OpenAI 配置

实现量较小，但不能满足“完全照搬 Fringe 设置内容”和 DeepSeek / 自定义兼容接口需求，因此不采用。

### 方案 C：把 AI 配置加入 `AppSettings`

可进入主数据备份链路，但会构成 SwiftData schema 变更并引入迁移、Widget 与备份兼容成本。AI 配置属于本机连接信息，当前没有跨设备同步要求，因此不采用。

## 4. AI 设置设计

### 4.1 设置入口

在 `SettingsCategory` 中加入 `AI`，图标使用 `sparkles`。Tab 内容和交互按 Fringe 当前设置实现：

- 服务商：OpenAI、DeepSeek、自定义兼容接口。
- Base URL：可编辑；选择 OpenAI 或 DeepSeek 时应用预设地址。
- API Key：默认安全输入，可切换显示/隐藏，可显式保存。
- 模型：未获取列表时允许手动输入；获取成功后用 Picker 选择。
- 操作：获取模型、测试连接。
- 状态：保存成功、模型获取结果、连接成功或失败提示。

### 4.2 存储

- 服务商、Base URL、模型：`UserDefaults`。
- API Key：独立的 Viabar Keychain service/account，不能复用 Fringe 的 service 标识。
- 拉取到的模型列表只保留在运行期内；切换服务商或 API Key 后清空。

### 4.3 网络协议

- 模型列表：`GET {baseURL}/v1/models`。
- 年度总结：`POST {baseURL}/v1/chat/completions`。
- Base URL 已包含 `/v1` 时避免重复拼接。
- 使用 Bearer API Key；请求超时沿用 Fringe 当前的 60 秒。
- 返回内容从首个非空 `choices[].message.content` 读取。

## 5. 年度报告界面

### 5.1 默认状态

- 现有 `560 × 520` 弹窗整体增大，实施时以约 `720 × 640` 为目标，并结合当前控件内边距静态校准。
- 年份选择行最右侧增加“AI 总结”按钮。
- 无完成记录时，AI 总结按钮与导出按钮保持不可用。
- 尚未生成 AI 总结时，导出按钮保持原行为：直接导出原始 Markdown，不额外弹出气泡。

### 5.2 请求状态

- 点击“AI 总结”后立即进入生成状态，按钮显示进度并防止重复请求。
- 生成期间保留左侧原始报告。
- 生成成功后展开右侧面板。
- 成功后按钮改为“重新生成”。重新生成期间保留当前结果，只有新请求成功才覆盖，以避免临时失败清空可用内容。
- 关闭弹窗时取消仍在进行的请求，避免关闭后的状态回写。

### 5.3 双栏展开状态

- 窗口只向右扩展，高度保持不变。
- 展开后的内容区使用两个等宽弹性列，原始报告与 AI 报告严格各占 50%。
- 两列之间使用现有分隔线语义。
- 左侧继续显示原始年度报告卡片列表。
- 右侧显示“AI 总结”标题、Markdown 标识和只读 Markdown 渲染内容。
- 两侧内容分别滚动，长 AI 输出不会推动窗口继续增高。
- 展开总宽度以约 `1120` 为目标；实施时确保扣除统一边距和中间分隔后两列内容宽度一致。

## 6. AI 输入与输出

### 6.1 输入

直接复用现有 `reportLines.joined(separator: "\n")` 作为用户输入。不要从 UI 卡片重新拼装第二份数据，以保持预览、原始导出和 AI 输入一致。

### 6.2 提示词约束

系统提示词要求模型：

- 只根据原始年报总结，不臆造项目、任务、数据或评价。
- 使用与当前 App 有效语言一致的语言输出。
- 返回可直接保存的 Markdown，不包裹代码块，不添加对话前缀。
- 建议包含年度概览、主要成果、推进特点和下一年可延续方向；缺乏证据的部分应省略。

### 6.3 结果生命周期

AI 结果只存在于当前 `YearlyReportView` 会话，不持久化、不进入备份。关闭弹窗或切换年份即丢弃；再次打开需重新生成。

## 7. 导出交互

### 7.1 无 AI 结果

点击“导出”直接打开现有原始年报文件导出器，保持当前功能不变。

### 7.2 有 AI 结果

点击“导出”弹出选择气泡，参考 CommuKit `PipelineRunnerView` 左上角解析器选择控件：

- 使用 plain 按钮触发 SwiftUI `Popover`，箭头朝向触发按钮。
- 气泡包含两个固定选项：“导出原始年报”和“导出 AI 总结”。
- 选项具有图标、圆角悬停底色；不显示选中勾号，因为两项是即时导出动作而不是持久选择。
- 因选项固定且只有两个，不加入搜索框。
- 选择后关闭气泡，再打开对应内容的系统文件导出器。

导出文件名：

- 原始年报：保持 `Viabar_年度报告_<年份>.md` 的现有本地化规则。
- AI 总结：`Viabar_AI总结_<年份>.md`，其中可见标签按 App 当前语言本地化。

## 8. 状态与并发

年度报告视图维护以下临时状态：

- 当前 AI 请求任务。
- 是否正在生成。
- AI Markdown 结果。
- AI 错误信息。
- 当前待导出的文档类型。
- 是否显示导出选择气泡与系统文件导出器。

每次请求捕获发起时的年份和原始 Markdown。响应返回时只有在年份仍一致且任务未取消的情况下才能写入结果，防止切换年份后的过期响应污染新页面。

## 9. 错误处理

- 配置不完整：提示先到设置完成 Base URL、API Key 和模型配置，不展开空面板。
- 认证失败：提示检查 API Key。
- 限流：提示稍后重试。
- 服务端或网络失败：显示简明错误并允许重新生成。
- 返回为空或格式无效：视为生成失败，不覆盖已有成功结果。
- 获取模型失败：继续允许手动输入模型名称，与 Fringe 行为一致。

错误文案放在年度报告界面内，不使用会中断上下文的多层弹窗。首次生成失败时维持单栏；重新生成失败时继续显示旧结果。

## 10. 国际化与可访问性

- 所有新增用户可见文案同步加入 macOS 英文和简体中文资源。
- AI 生成语言根据 `EffectiveAppLanguage` 明确写入提示词，而不是依赖模型猜测。
- 图标按钮提供 help 与 accessibility label。
- 生成状态通过可见进度和禁用状态表达。
- Markdown 内容允许文本选择。

## 11. 代码边界

建议按现有结构拆分为：

- AI 服务商类型与配置值对象。
- Keychain secret store。
- AI 配置 store。
- OpenAI 兼容文本服务。
- 年度报告专用总结服务或提示词构造器。
- 设置 AI 面板。
- `YearlyReportView` 的双栏、状态与导出入口。

不在 `YearlyReportView` 内直接实现 Keychain 和 HTTP 编解码；不创建新的年度报告数据模型或持久化实体。

## 12. 静态验证与后续验证

本轮实施默认不编译、不运行测试。完成代码后至少执行：

- 静态搜索确认设置 Tab、UserDefaults、Keychain service、端点和年度报告状态链路。
- 检查所有新增中英文 key 成对存在。
- `plutil -lint Viabar/en.lproj/Localizable.strings Viabar/zh-Hans.lproj/Localizable.strings`。
- `plutil -lint Viabar.xcodeproj/project.pbxproj`。
- `git diff --check`。
- 检查 diff 中没有 `@Model`、Schema、备份格式和 Widget schema 改动。

只有用户后续明确授权时才编译或运行测试。届时应覆盖：

- Base URL `/v1` 去重。
- 模型列表和聊天响应解码。
- 不同 HTTP 错误映射。
- 年份切换取消和过期响应保护。
- 原始/AI 导出内容与文件名选择。
- 窗口展开后 50/50 布局和 Popover 交互。

## 13. 验收标准

1. 设置中出现 AI Tab，内容与 Fringe 当前 AI 设置能力一致。
2. 年度报告默认弹窗明显比当前 `560 × 520` 更宽、更高。
3. AI 只接收当前原始年报 Markdown。
4. 生成成功后窗口向右展开，左右区域严格各占 50%。
5. AI 内容以只读 Markdown 正常显示，并允许重新生成。
6. 切换年份不会保留或误导出旧年份 AI 总结。
7. 无 AI 总结时导出行为完全不变。
8. 有 AI 总结时导出气泡外观与交互参考 CommuKit 解析器选择 Popover，可选择两类 Markdown。
9. AI 配置和结果不引入 SwiftData schema 或备份格式变更。
10. 中英文界面文案完整，静态检查通过。
